# Android / iOS 规划（不执行）

> 状态：**纯规划文档**。本仓库不包含 Android / iOS 工程、Gradle / Xcode 配置、Capacitor 项目或可安装包。移动端的任何实现都需要在独立阶段立项、评估与验收。

## 为什么先不做

移动端不是“把 WebUI 塞进 WebView”这么简单：

- 模型 75 MB–3 GB，移动网络、存储、后台下载策略完全不同；
- 手机内存与热预算有限，长音频必须分块；
- NPU 运行时碎片化（NNAPI / QNN / Core ML）；
- iOS 后台执行窗口与 App Store 审核约束；
- 模型许可证与再分发需要逐个确认。

当前版本先把 Whisper 下载、加载、CPU / CUDA 转写与导出在桌面 / 服务器上做扎实，同时保持 API 与模型格式可复用。

## 复用边界

```text
┌──────────────────────────────────────────┐
│ Fluent WebUI（现有 React 应用）           │
│ 通过 WebView / 受控 Bridge 复用            │
└──────────────────┬───────────────────────┘
                   │ 同一套 HTTP JSON 契约
┌──────────────────▼───────────────────────┐
│ 移动端容器（未来）                         │
│ 文件选择 · 前台服务 · 权限 · 生命周期       │
└──────────────────┬───────────────────────┘
                   │ Runtime Adapter
┌──────────────────▼───────────────────────┐
│ 移动推理运行时（未来）                     │
│ whisper.cpp / ORT QNN / NNAPI / Core ML   │
└──────────────────────────────────────────┘
```

原则：

1. **UI 复用**：Fluent WebUI 保持一致设计与交互，不维护第二套设计语言。
2. **API 复用**：模型目录、任务状态、导出格式保持同一契约。
3. **运行时独立**：移动端不复用桌面 CTranslate2；按平台选择端侧运行时。
4. **能力诚实**：只有真实可运行的设备后端才出现在选择器中。

## Android 规划

### 容器

- Kotlin 原生壳，`WebView` 承载 Fluent WebUI；
- 受控 JS Bridge 暴露：
  - 文件选择 / SAF；
  - 前台服务状态；
  - 网络类型与存储空间；
  - 电量、热状态；
  - 模型下载任务。
- 不使用 Capacitor 作为首选，因为大文件下载、前台服务、热管理需要原生控制。

### 推理

候选路径按优先级：

1. **whisper.cpp**（Vulkan / CPU）——模型格式紧凑、端侧成熟，优先验证；
2. **ONNX Runtime + NNAPI**——通用 NPU / GPU，但 Whisper 算子覆盖需验证；
3. **Qualcomm QNN**——骁龙设备，性能潜力最大，设备碎片化严重；
4. **厂商 SDK**——按机型白名单接入。

设备选择策略：

- 仅当运行时初始化成功并通过短音频 smoke test 才启用 NPU；
- 失败自动回退 GPU → CPU；
- 首启按内存与芯片档位推荐 Tiny / Base；
- 长音频分块 + VAD，避免一次性加载。

### 下载与存储

- Foreground Service + WorkManager 管理大模型下载；
- 下载到应用私有目录，manifest 校验；
- 蜂窝网络默认不自动下载 > 100 MB；
- 支持暂停 / 恢复（Range）；
- 存储不足时阻止开始并展示所需空间；
- 模型可删除，转写历史独立保留。

### 硬约束

- 内存：Tiny / Base 优先；Small 仅中高端设备；
- 热：连续转写降频，必要时暂停；
- 电量：低于阈值时提示；
- 后台：Android 前台服务需常驻通知；
- 安全：模型与音频不进入共享存储；导出走 SAF。

### 验收（未来）

- 10 分钟音频在目标机型完成转写且不 OOM；
- 断网 / 切网 / 杀进程后下载可恢复；
- NPU 不可用时正确回退且 UI 不误导；
- 字幕导出与桌面端格式一致；
- 通过目标 API level 的权限与前台服务审核。

## iOS 规划

### 容器

- SwiftUI 原生壳 + `WKWebView` 承载 Fluent WebUI；
- 原生能力：文件选择、分享、后台 URLSession、存储、电量；
- 不引入第二套 UI 设计。

### 推理

- **Core ML / ANE** 优先，调研 WhisperKit 等成熟实现；
- GPU 走 Metal；
- CPU 兜底；
- 模型必须转换为 Core ML 可接受的格式，或使用运行时自带格式；
- App 内存上限严格，需要分段编码 / 解码与及时释放。

### 下载与存储

- URLSession 后台传输仅在系统允许时继续；
- 大模型提示 Wi-Fi 与磁盘空间；
- 模型存 Application Support，标记不备份或按需备份；
- 支持删除与重新校验。

### 硬约束

- 后台执行窗口有限，长任务需要前台提示；
- App Store 审核：模型下载、许可、隐私声明；
- 不同设备 ANE 能力差异大；
- 模型分发方式（应用内下载 vs 内置）需要法务确认。

### 验收（未来）

- 目标设备上 10 分钟音频转写稳定性；
- 后台切换、来电、锁屏后的任务恢复；
- 内存峰值低于系统限制；
- 模型下载与删除符合 App Store 指南；
- 与桌面端共享导出格式。

## 共享契约

移动端接入前需要固定：

- 模型目录字段与 manifest 版本；
- 任务状态机：`queued → running → completed | failed | cancelled`；
- 导出格式：SRT / VTT / TXT / JSON；
- 设备能力对象：`kind / backend / status / for_asr`；
- 错误码与用户提示；
- 模型校验规则（必需文件、大小、哈希可选）。

## 分阶段计划

| 阶段 | 内容 | 产出 |
| --- | --- | --- |
| P0（当前） | 桌面 / 服务器 Whisper 全链路 | 可运行 WebUI + API + 桌面壳源码 |
| P1 | 移动端技术验证（不进入产品） | whisper.cpp / ORT / Core ML 单机型 benchmark |
| P2 | Android 原型 | 容器、下载、CPU 转写、导出 |
| P3 | Android NPU | NNAPI / QNN 适配与回退 |
| P4 | iOS 原型 | WKWebView、Core ML、后台策略 |
| P5 | 产品化 | 签名、商店、隐私、许可证、灰度 |

P1 之前不创建移动端工程。

## 风险清单

- 端侧运行时性能与模型格式不匹配；
- NPU 算子覆盖不足，实际只能 CPU；
- 大模型下载失败率高、蜂窝流量成本；
- 手机热降频导致长音频不可用；
- iOS 后台限制与审核；
- 模型许可证不允许随应用分发；
- WebView 与原生 Bridge 的安全边界。

## 明确不做

- 本版本不生成 Android / iOS 安装包；
- 不添加 Gradle / Xcode 工程；
- 不发布移动端应用商店版本；
- 不承诺移动端性能指标；
- 不把桌面 CTranslate2 直接移植到移动端。
